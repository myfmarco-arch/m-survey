# 跨波次可比性

本服务检查新一波问卷能否和上一波或历史结果比较。

触发条件：修改已回收问卷、追踪研究、或用户要求与上一波、去年、历史基准比较。

## 为什么需要检查

追踪数据的价值在于可比。题干、选项、量表、分母或题序的小改动，都可能让变化来自问卷本身，而不是用户。实际项目中常见的漂移包括：人群描述措辞改了几个字、品牌合并口径（某品牌是否含子品牌）不一致、年龄分段重新切分。

## 比较什么

逐题比较以下内容。追踪题优先沿用上一波原文，只改必要的版本名。

| 对象 | 改动示例 | 默认判断 |
|---|---|---|
| 题干 | 措辞调整 | 需加注；改变对象或时间范围时不可比 |
| 量表 | 点数、锚点文字、方向 | 不可比 |
| 选项 | 增删选项、改写选项、合并口径 | 受影响选项不可直接比较；多选题的其余选项需加注 |
| 编码 | 同一编码代表不同含义 | 不可比，且会造成数据错误 |
| 显示条件 | 分母改变，例如从全部用户改为使用者 | 需加注；比例需按同一分母重算 |
| 题序 | 追踪题前面新增题目，尤其是刺激曝光 | 需加注 |
| 样本 | 来源、渠道、甄别条件、回收时间窗改变 | 需加注；差异不能直接解释为变化 |

有代码执行环境，且两波都有 QuestionnaireSpec 时运行：

```bash
python3 scripts/diff_waves.py previous-spec.yaml current-spec.yaml
```

题号在两波之间变了时，用 `--map 旧题号:新题号` 对应。

## 交付格式

可比性清单写进研究简报与方案的方法方案小节，不附在问卷后面：

| 题号 | 判断 | 原因 | 处理 |
|---|---|---|---|
| Q1 | 可比 | 题干、量表和分母未变 | 直接比较 |
| Q3 | 需加注 | 新增 1 个模块行 | 只比较两波都有的行 |
| Q5 | 不可比 | 量表从 5 分改为 10 分 | 不做跨波比较，或下一波起重新建立基线 |

没有拿到上一波原问卷时，不声称可以比较；在需确认项中要求提供原题。

## 规则

| rule_id | 检查 | 默认严重程度 | 脚本可检 |
|---|---|---|---|
| `tracking.wording-changed` | 追踪题题干改动已标注；改变对象或时间范围的判为不可比 | `warning` | 是 |
| `tracking.scale-changed` | 追踪题的点数、锚点或方向没有改变；改变时判为不可比 | `error` | 是 |
| `tracking.options-changed` | 选项增删或改写已标注影响范围 | `warning` | 是 |
| `tracking.code-meaning-changed` | 同一编码在两波中代表相同含义 | `error` | 是 |
| `tracking.base-changed` | 显示条件改变（分母改变）已标注，并说明比较时的分母 | `warning` | 是 |
| `tracking.position-changed` | 追踪题之前新增题目或题序改变时已标注可能的顺序效应 | `info` | 是 |
| `tracking.sample-changed` | 样本来源、渠道、甄别条件或时间窗改变时已说明，不把差异直接解释为变化 | `warning` | 否 |
| `tracking.source-required` | 声称跨波可比前已取得上一波原问卷 | `error` | 否 |
| `tracking.comparability-stated` | 交付物列出可比、需加注和不可比的题目 | `warning` | 否 |
