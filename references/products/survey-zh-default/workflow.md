# 官方中文问卷工作流

本文件是 `survey-zh-default` 的默认工作流。它是产品选择，不是所有兼容产品必须复制的唯一流程。

## 设计顺序

```text
业务决策
→ 研究问题
→ 主要指标和分析方法
→ 分析对象和比较关系
→ 研究方法
→ 样本与配额
→ 收集已有材料（上一波问卷、问题清单、舆情、埋点）
→ 问卷模块和题序
→ 题目和选项（标注选项来源）
→ 显示与跳转说明
→ 质量控制和清洗规则
→ 时长估算和删减
→ 编码配置
→ 验证
```

每道题服务于研究问题、样本控制、质量控制或问卷内容逻辑。不能说明用途的题目应删除。

## 交互默认值

- 先从用户材料提取已知信息，不重复询问。
- 第一轮最多提出 6 个编号问题。一个编号问题可以包含紧密相关的子问（例如“评价什么对象？受访者用过吗？”），但不把无关问题合并凑数。这是官方产品默认值，可由 overlay 覆盖。
- 需要封闭选项列表（问题、原因、功能、品牌）而用户没有给材料时，把“有没有上一波问卷、问题清单、舆情或客服分类”放进首轮问题。
- 涉及跨波比较时，要求提供上一波原问卷。
- 信息充分时直接继续。非关键缺口使用显式假设。
- 复杂或高风险方法先交付简短研究简报，再进入完整问卷。
- 简单且信息充分的任务一次完成。

## 常用测量链路

| 任务 | 默认链路 |
|---|---|
| 体验诊断 | 使用资格 → 整体评价 → 一级方向评分 → 低分方向原因 → 场景 → 功能 → 具体问题 → 改进建议 |
| 卖点复盘 | 资格 → 整体评价（卖点曝光前）→ 卖点状态（不知道 / 知道无影响 / 知道且有影响）→ 吸引与不吸引原因 → TOP1 → 用过卖点的体验评价 |
| 版本上线回访 | 版本与使用时长核验 → 整体评价 → 与上一版本比较 → 新功能认知与使用 → 用过功能的评价 → 问题发生、频率和影响 → 最希望先解决的问题 |
| 购买决策 | 购买背景和角色 → 对比范围 → 信息渠道 → 关注因素 → 相对取舍 → 关键因素深挖 |
| 新功能需求 | 当前行为 → 未满足问题 → 使用场景 → 功能需求 → 需求类型或优先级 → 使用阻碍 |
| 概念测试 | 使用资格 → 随机展示 → 单方案评价 → 方案比较 → 高低分原因 → 最佳方案 |
| 用户招募 | 基本条件 → 设备或行为资格 → 深度经验 → 表达能力 → 时间意愿 → 联系方式 |

题序规则和链路细节见 [题目工艺](../../modules/knowledge/question-craft.md)。

## 问卷负担

- 只向用户展示与其经历有关的模块。
- 使用显示逻辑、答案引用、循环和个人 TOP 因素追问控制长度。
- 长列表随机普通选项，特殊选项按语义固定位置。
- 长矩阵拆分、只显示相关行，或只追问关键项目。
- 开放题只用于补充遗漏、解释原因、收集案例或筛选表达能力。
- 时长按 [受访负担](../../services/validation/respondent-burden.md) 估算。卷首语的时长不低于典型路径，不高于最长路径。
- 方法方案不为求全而罗列不采用的方法。用户或需求方点名了某个方法，或需求措辞容易被误读成另一种方法时，才用一两句说明为什么不采用。

交付格式见 [模板](templates.md)。
