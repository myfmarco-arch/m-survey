# 新功能需求

## 功能候选集优先级

**适用**：团队已经有一组同层级候选功能，需要理解相对取舍和使用背景。

**核心结构**：

```text
当前行为和使用资格
→ 未满足场景和问题
→ 候选功能理解检查
→ 相对取舍任务
→ 关键功能深挖
→ 采用阻碍
```

**关键设计**：

- 候选项保持同一层级，不将问题、解决方案和具体功能混在同一列表。
- 需求类型使用 KANO；相对排序使用 MaxDiff。
- 自报喜欢不直接解释为实际采用。
- 只对关键候选项追问场景和阻碍，控制问卷负担。

## 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 候选列表混入问题、解决方案和具体功能 | 相对排序没有意义 | 先统一层级，再做排序或 MaxDiff |
| 候选项之间互相包含（“硬件配置高”和“续航强”） | 重要度被重复计算 | 拆成互不重叠的条目 |
| 题干预设重要性（“您非常关注……吗”） | 高估需求 | 中性问法，或用取舍任务 |
